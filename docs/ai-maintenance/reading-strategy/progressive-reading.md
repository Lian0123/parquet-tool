# Progressive Reading Strategy

1. Read only `entry.md` first.
2. Read one task or feature index.
3. Use `rg` for symbols, commands, and tests; read only nearby matches.
4. Read risk or build docs only for cross-boundary changes.

Stop when you know the entry point, data flow, files, risks, and validation. Keep one authoritative location per fact, use stable paths and symbols, and write unknown when evidence is missing.
