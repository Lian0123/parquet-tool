QUESTIONS & ANSWERS

Parquet conversion FAQ

How do I convert CSV to Parquet?

Choose or drop a UTF-8 CSV with a header, check the preview, select Parquet, then convert and download. The project core writes uncompressed PLAIN encoding.

How do I convert Parquet to JSON or CSV?

Choose a flat Parquet file, preview it, select JSON or CSV, then convert and download. CSV supports comma, semicolon and Tab delimiters; JSON exports an array of objects.

Are files uploaded to a server?

No. Reading, previewing and conversion run in a Web Worker in your browser. The engine is served with the site; files are not sent to a third-party conversion service.

What are the size limits?

Up to 20 MiB per file, 100,000 rows, 200 columns and 2,000,000 cells. Only flat tables are supported; nested and binary fields are not. Decoding compressed files uses more memory. You can cancel processing.

How are large integers, nulls and mixed types handled?

INT64 exports to JSON / CSV as decimal strings. Unsafe JSON numbers are rejected; use quoted strings. Empty CSV fields and missing JSON fields become null. Mixed-type columns and dates are stored as text.

Can I exchange Parquet files with the current CLI?

Yes. The browser and Node.js / CLI share this project’s C++ core, supporting uncompressed PLAIN data page v1. Legacy project schemas remain readable. Compression, nested columns and other logical types are unsupported; full metadata is not preserved.

Local processing. Useful results.

Files are not sent to a server. All conversion code is served with this site; processing does not use a third-party service.

Shared core with the local version

The browser uses this project’s C++ core through WebAssembly, sharing the Parquet implementation with Node.js / CLI. It supports uncompressed PLAIN data page v1; other codecs and encodings are explicitly rejected.

Supported data

Supports UTF-8 CSV with a header, JSON object arrays or { rows: [...] }, and flat Parquet. A JSON schema block is not applied; types are inferred from data.

Mixed-type columns become text. Keep dates and very large JSON integers as strings. Nested and binary fields are not supported. Limit: 200 columns and 2,000,000 cells.
